1. Сервис парсинга ISO 20022 / SWIFT-подобных сообщений

Назначение
Приём, валидация и преобразование внешних финансовых сообщений во внутренний канонический формат для дальнейшей обработки в АБС/платёжном ядре.

Функциональные требования

    Приём сообщений из MQ, файлового хранилища, API или шлюза.

    Поддержка форматов: ISO 20022 (pacs.008, pacs.009, pain.001, camt.053), SWIFT MT103/MT202, XML/CSV-выгрузки.

    Определение типа сообщения и выбор схемы валидации.

    XSD/схемная валидация, проверка обязательных полей, валют, BIC/IBAN, контрольных сумм.

    Маппинг во внутреннюю модель: платёж, поручение, выписка, статус.

    Идемпотентность по EndToEndId / UTI / MsgId.

    Обработка ошибок: retry, DLQ, алерты, ручной разбор.

    Аудит: кто, когда, что принял и преобразовал.

    Метрики: количество сообщений, ошибок, задержки.

Стек

    Python 3.11+, FastAPI, lxml, xmlschema, Pydantic.

    PostgreSQL, SQLAlchemy, Alembic.

    RabbitMQ / Kafka, Redis.

    Docker, Kubernetes, Prometheus/Grafana, ELK/OpenSearch.

    pytest, CI/CD.

Интеграции
АБС, платёжный шлюз, SWIFT/СПФС, внутренние очереди, DWH.

НФТ и безопасность

    Задержка обработки — до 200 мс на сообщение.

    Горизонтальное масштабирование, отказоустойчивость.

    Шифрование каналов, ГОСТ TLS, разграничение доступа.

    Соответствие 152-ФЗ, PCI DSS, требованиям Банка России.

    Хранение аудита — не менее 5 лет.

Критерии приёмки

    Корректный разбор всех заявленных типов сообщений.

    Ошибки валидации не приводят к падению сервиса.

    Повторная доставка не создаёт дубль.

    Есть метрики, логи и алерты.

2. Внутренний CLI для операциониста

Назначение
Безопасный инструмент для ручных операций back-office: просмотр, поиск, повтор, сверка и выгрузка данных.

Функциональные требования

    Аутентификация через SSO/AD, RBAC по ролям.

    Просмотр выписок по счёту за период.

    Поиск платежей по ID, счёту, дате, статусу.

    Повторный запуск зависших операций (retry).

    Блокировка/разблокировка счетов и платежей.

    Запуск сверки и просмотр расхождений.

    Экспорт в CSV/XLSX.

    Подтверждение критичных действий.

    Полный аудит действий операциониста.

Стек

    Python, Typer / Click, Rich.

    httpx / requests для вызова внутренних API.

    pandas, openpyxl для выгрузок.

    keyring для работы с секретами.

    PyInstaller — опционально для поставки.

    pytest.

Интеграции
Внутренние API, АБС, DWH, SSO/AD, система аудита.

НФТ и безопасность

    Запрет прямого доступа к БД.

    Маскирование ПДн и платёжных данных в выводе.

    Работа только в закрытом контуре.

    Журналирование всех команд и результатов.

    Разграничение прав: операционист, старший операционист, администратор.

Критерии приёмки

    Операционист может выполнить типовые операции без SQL.

    Критичные действия требуют подтверждения.

    Все действия попадают в аудит.

    Ошибки API обрабатываются понятными сообщениями.

3. Сервис кредитного скоринга

Назначение
Автоматический расчёт скорингового балла, вероятности дефолта и решения по кредитной заявке.

Функциональные требования

    Приём кредитной заявки из CRM/фронта.

    Валидация заявки и обязательных полей.

    Запрос данных из внутренних систем и БКИ.

    Расчёт признаков: доход, нагрузка, история, регион, продукт.

    Применение бизнес-правил и ML-модели.

    Выдача: score, PD, решение (одобрить/отказать/на доработку), лимит, ставка.

    Объяснение решения: топ-факторы, feature importance.

    Версионирование моделей и правил.

    Аудит заявки и решения.

    Мониторинг дрифта модели и качества.

Стек

    Python, FastAPI, Pydantic.

    scikit-learn, XGBoost / LightGBM.

    MLflow — реестр моделей.

    PostgreSQL, Redis, Kafka, Airflow.

    Docker, Kubernetes, Prometheus/Grafana.

    Evidently AI — мониторинг дрифта.

    pytest, CI/CD.

Интеграции
CRM/фронт, БКИ, АБС, DWH, антифрод, система лимитов.

НФТ и безопасность

    Время отклика — до 500 мс на скоринг.

    Доступность — 99,9%.

    Explainability: решение должно быть объяснимо.

    Регулярный пересмотр и валидация модели.

    Шифрование, RBAC, аудит.

    Соответствие 152-ФЗ и внутренним кредитным политикам.

Критерии приёмки

    Скоринг возвращает стабильный результат при повторных запросах.

    Решение объяснимо и воспроизводимо.

    Модель и правила версионируются.

    Есть мониторинг качества и дрифта.

    Все заявки и решения логируются.
